# GOLDEN HAIR SALON

אתר לניהול תורים במספרת גברים ולמכירת מוצרים הקשורים לשיער.

פרויקט גמר — הנדסאי תוכנה.
מגיש: אריאל יצחק קפלן.

## מה האתר עושה

האתר מאפשר ללקוחות המספרה לנהל את התורים שלהם באופן עצמאי — לקבוע תור, לצפות בתורים
קיימים, לשנות תור ולבטל תור — במקום להתקשר לספר ולתפוס אותו באמצע עבודה. בנוסף יש באתר
חנות שבה אפשר לרכוש מוצרים הקשורים לשיער, כמו מכונות תספורת וג'ל לשיער.

במערכת יש שלושה סוגי משתמשים:

| משתמש | מה הוא יכול לעשות |
|---|---|
| לקוח | הרשמה והתחברות, הזמנת תור, צפייה/שינוי/ביטול תור, רכישה בחנות, עדכון פרופיל |
| נותן שירות (ספר) | צפייה ביומן התורים שנקבעו אליו בלבד, עריכת ימי ושעות העבודה שלו |
| מנהל ראשי | ניהול משתמשים והרשאות, צפייה בכל התורים, ניהול מוצרי החנות וההזמנות |

## טכנולוגיות

- **צד לקוח:** React 18 עם Vite ו‑React Router
- **צד שרת:** Node.js + Express
- **מסד נתונים:** MongoDB עם Mongoose
- **אבטחה:** bcrypt להצפנת סיסמאות, JWT לניהול הזדהות

## הרצה מהירה

הדרך המהירה ביותר לראות את האתר עובד, בלי להתקין MongoDB בכלל:

```bash
# חלון ראשון - השרת עם מסד נתונים זמני בזיכרון
cd server
npm install
npm run dev:memory

# חלון שני - צד הלקוח
cd client
npm install
npm run dev
```

ואז לפתוח את הדפדפן בכתובת **http://localhost:3000**

> שים לב: במצב הזה כל הנתונים נמחקים כשסוגרים את השרת. זה מיועד לבדיקה בלבד.

## הרצה עם MongoDB אמיתי

1. צור חשבון חינמי ב‑[MongoDB Atlas](https://www.mongodb.com/cloud/atlas) או התקן MongoDB מקומית.
2. בתיקיית `server`, העתק את `.env.example` לקובץ בשם `.env` ומלא את הפרטים:

```
MONGO_URI=mongodb+srv://user:password@cluster.mongodb.net/golden_hair_salon
JWT_SECRET=מחרוזת-ארוכה-ואקראית-משלך
PORT=5000
```

3. הרץ את סקריפט ההזרעה כדי ליצור נתוני התחלה:

```bash
cd server
npm run seed
npm start
```

## המרכיב האלגוריתמי

הלב של המערכת נמצא ב‑[server/services/slots.js](server/services/slots.js) — חישוב השעות
הפנויות של ספר בתאריך נתון.

החישוב בונה את כל משבצות הזמן האפשריות ביום העבודה, ואז מסנן מהן את המשבצות שאינן פנויות:
כאלה שמתנגשות בתור קיים, כאלה שהתספורת בהן תחרוג משעת הסגירה, וכאלה שכבר עברו.

הבדיקה של התנגשות בין שני טווחי זמן:

```
overlap = (candidateStart < existingEnd) AND (existingStart < candidateEnd)
```

הסימן הוא `<` ולא `<=` בכוונה — תור שמסתיים ב‑10:00 ותור שמתחיל ב‑10:00 אינם מתנגשים.

התיאור המלא של האלגוריתם, כולל הפסאודו‑קוד ודוגמת הרצה, נמצא בסעיף 10 של ספר הפרויקט.

## הקשר בין הקוד לספר הפרויקט

כל תהליך מערכת (SUC) שמוגדר ב‑SRS ממומש בקוד, כדי שיהיה אפשר לעקוב מהספר אל הקוד:

| SUC | התהליך | הקוד |
|---|---|---|
| SUC-1 | הרשמה לאפליקציה | `routes/users.js` → `POST /register` |
| SUC-2 | התחברות לאפליקציה | `routes/users.js` → `POST /login` |
| SUC-3 | הזמנת תור | `routes/appointments.js` + `services/slots.js` |
| SUC-4 | צפייה בתורים קיימים | `routes/appointments.js` → `GET /my` |
| SUC-5 | שינוי תור | `routes/appointments.js` → `PUT /:id` |
| SUC-6 | ביטול תור | `routes/appointments.js` → `DELETE /:id` |
| SUC-7 | רכישה בחנות | `routes/orders.js` → `POST /` |
| SUC-8 | עדכון פרופיל אישי | `routes/users.js` → `PUT /profile` |
| SUC-9 | ניהול יומן ושעות עבודה | `routes/appointments.js` + `routes/schedule.js` |
| SUC-10 | ניהול משתמשים והרשאות | `routes/users.js` → `PUT /:id/role` |
| SUC-11 | ניהול תורים כולל | `routes/appointments.js` → `GET /all` |
| SUC-12 | ניהול החנות וההזמנות | `routes/products.js` + `routes/orders.js` |

## אבטחת מידע

- סיסמאות נשמרות מוצפנות בלבד (bcrypt עם salt), אף פעם לא כטקסט גלוי
- ההזדהות מבוססת JWT, והאסימון מכיל את תפקיד המשתמש
- **בדיקת ההרשאות מתבצעת בצד השרת** ולא בצד הלקוח — הסתרת כפתור במסך אינה אבטחה
- נעילת חשבון למשך חצי שעה אחרי 5 ניסיונות התחברות כושלים
- הודעת שגיאה כללית בהתחברות, כדי לא לחשוף אילו כתובות מייל רשומות במערכת
- מחירי ההזמנה מחושבים בשרת מתוך מסד הנתונים, ולא נלקחים ממה שהדפדפן שלח
- פרטי כרטיס אשראי אינם נשמרים בשום מקום. הסליקה בפרויקט זה היא הדמיה בלבד
